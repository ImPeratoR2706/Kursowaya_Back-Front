ЗАДАЧА МОДЕЛИ
-------------
Прогноз неявки клиента (no-show): вероятность того, что клиент не придёт на запись.
Это бинарная классификация на CatBoost (CatBoostClassifier).

Файл модели:
  Backend/apps/salon/ai_module/no_show_model.cbm

Метаданные (версия, список признаков, validation_accuracy с последнего обучения/оценки):
  Backend/apps/salon/ai_module/model_meta.json


ПРИЗНАКИ (СОБИРАЮТСЯ В ml.py — build_feature_dict_for_appointment)
------------------------------------------------------------------
  weekday                      — день недели начала записи, по-русски: Пн … Вс (категориальный)
  hour                         — час начала
  client_cancel_count_90d      — отмены (статус cancelled) у клиента за 90 дней ДО этой записи
  client_no_show_count_90d     — неявки (статус no_show) у клиента за 90 дней ДО этой записи
  lead_time_days               — полные дни между created_at записи и start_datetime
  payment_status               — не_оплачено / оплачено / частично (категориальный; refunded -> частично)
  master_appointments_same_day — сколько у мастера других записей в тот же календарный день
  master_id                    — id мастера строкой (категориальный)

Категориальные для CatBoost: weekday, payment_status, master_id.

Через API можно передать feature_overrides — подменить только эти ключи перед инференсом.


ИНФЕРЕНС (ПРЕДСКАЗАНИЕ)
-----------------------
1) upsert_ai_data_for_appointment (services.py)
   Проверяет: есть клиент, мастер, услуга, время начала; иначе возвращает None.
   При отсутствии .cbm или ML-пакетов выбрасывает AiInferenceUnavailable
   (API predict-no-show -> HTTP 503; сигнал post_save -> запись в лог, без отката транзакции).

2) predict_no_show (ml.py)
   — импорт pandas, catboost (без них — AiInferenceUnavailable / подсказка в API и логах)
   — загрузка no_show_model.cbm (если файла нет — та же ошибка с подсказкой train_no_show_model)
   — одна строка признаков -> Pool -> predict_proba
   — вероятность класса «неявка» — вторая колонка proba (класс 1), иначе первая
   — результат в процентах -> Aidata.prediction_probability

Дополнительно:
  admin_recommendation  — текст по порогам вероятности (recommend_for_admin)
  master_risk_color     — green / yellow / red (risk_color_for_master)
  inference_time_ms     — время вызова
  input_features        — снимок признаков

Связь с БД: модель Aidata, одна запись на одну запись (Appointment), update_or_create.


«ОБУЧЕНИЕ» ФАЙЛА .cbm И ОЦЕНКА В ПРОЕКТЕ (ВАЖНО)
------------------------------------------------
A) Обновление файла модели no_show_model.cbm (CatBoost)

   Management-команда (из каталога Backend):
     python manage.py train_no_show_model [--n N] [--min-accuracy 0.75] [--flip-prob] [--seed]

   По умолчанию обучение идёт на синтетическом наборе, согласованном с признаками
   ml.FEATURE_NAMES; holdout-accuracy записывается в model_meta.json (поле
   validation_accuracy). Параметр --min-accuracy задаёт желаемый порог на валидации
   (при необходимости команда делает несколько попыток с меньшим шумом метки).

   В docker-compose при первом старте backend, если .cbm отсутствует, выполняется
   train_no_show_model (см. INSTRUKCIYA_DOCKER.txt).

   Для реального салона синтетическую модель нужно заменить своим обучением на
   исторических данных с той же схемой признаков.

B) Оценка уже сделанных предсказаний (НЕ переобучение .cbm)

   POST /api/ai-training-runs/run/ (только admin) делает следующее:
     — берёт Aidata с заполненным target_value (разметка: 0/1 — факт неявки для оценки)
     — берёт УЖЕ сохранённую моделью prediction_probability, делит на 100,
       сравнивает с порогом из запроса (по умолчанию 0.5) -> предсказанный класс
     — сравнивает с target_value -> TP, FP, TN, FN, accuracy, precision, recall, F1
     — сохраняет срез в AiTrainingRun (история для AI-панели админа)

   Это оценка качества уже сделанных предсказаний на размеченных данных,
   а не обучение нового файла .cbm с нуля.

Разметка target_value может появиться, например:
  — при upsert_ai_data_for_appointment(..., target_value=...) как в команде
    generate_ai_tests (демо/тесты)
  — при ручном редактировании через API ai-data и т.п.

Команда backfill_ai_data — прогон инференса по записям, создание/обновление Aidata,
без обучения файла .cbm (при недоступной модели прекращает попытки и сообщает в выводе).


ИНТЕРФЕЙС
---------
Мастер: в дашборде записей кнопка «Рассчитать» ->
  POST .../appointments/{id}/predict-no-show/
  Обновляется Aidata, в списке — цвет риска и процент.

Админ: AI-панель (AiDashboard):
  /api/ai/model-info/ — информация о модели
  /api/ai-data/ — все AI-данные
  запуск «оценки» -> POST /api/ai-training-runs/run/


КРАТКАЯ ТАБЛИЦА
----------------
Что предсказывает ИИ?       Вероятность неявки клиента.
Какая модель?               CatBoost, файл no_show_model.cbm.
Где «учится» файл .cbm?     Команда train_no_show_model (синтетика по умолчанию)
                            или ваш пайплайн вне проекта с той же схемой признаков.
Где оценка качества?        POST /api/ai-training-runs/run/ по target_value -> AiTrainingRun.
Откуда признаки?            История записей клиента, оплата, загрузка мастера в день и т.д. (ml.py).
